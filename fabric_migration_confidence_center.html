№1 — 214 external tables over Parquet/CSV are not fully supported in Fabric WarehouseHigh risk
PlannedWarehouse214 assets
Fabric Warehouse supports OPENROWSET for Parquet/CSV access, but external table parity (as used in Synapse PolyBase patterns) is planned and not yet fully available. 214 external table definitions could not be directly migrated using the Warehouse Migration Assistant. 18 downstream BI reports depend on these tables.
Remediation options:
Convert to Delta tables Use Lakehouse shortcuts OPENROWSET views where acceptable Wait for roadmap if ext-table governance required
№2 — 38 linked services need Fabric connection mappingHigh risk
In progressPipelines38 assets
Pipeline activities using unmapped connections remain deactivated after migration. 38 linked services have not been mapped to Fabric connections. Activities using these connections cannot be reactivated until mapping, authentication, and secret references are validated.
Remediation options:
Map each linked service to Fabric connection Validate authentication method Confirm Key Vault secret references Reactivate and test affected activities
№3 — 23 pipeline activities deactivated after test migrationHigh risk
BlockedPipelines23 activities
23 activities are deactivated because required Fabric connections were not mapped, or matching Fabric notebooks/Spark job definitions do not yet exist. These activities span 11 pipelines in the financial data loading workflow. Pipeline orchestration is incomplete until all upstream artifacts are migrated and mapped.
Remediation options:
Migrate Spark artifacts first (prerequisite) Map all notebook/Spark job dependencies Reactivate activities sequentially Run end-to-end validation tests
№4 — 12 private networking dependencies require validationMedium risk
Needs reviewSecurity12 dependencies
Secure access patterns for Fabric workloads vary by workload type. Private Link and workspace-level private links exist in Fabric, but support has workload-specific limitations. All 12 private networking dependencies must be validated for firewall rules, VNet gateway configuration, and compliance with Contoso's restricted financial data requirements.
Remediation options:
Review Fabric Private Link docs Validate VNet / firewall rules Test Warehouse + Lakehouse + Pipeline access paths Confirm restricted-data compliance
№5 — 46 Key Vault references need compatibility checkMedium risk
Needs reviewSecurity46 references
Azure Key Vault references exist in Fabric, but connection support and setup limitations must be validated. Secret rotation behavior, supported connection types, and workspace/tenant configuration must be confirmed before production cutover.
Remediation options:
Validate supported AKV connection types Confirm secret rotation behavior Test workspace/tenant configuration
№6 — 9 CI/CD workflows need Warehouse deployment safety reviewMedium risk
Needs reviewDevOps9 workflows
Warehouse source control and deployment is improving but remains a migration-confidence risk area. Enterprise teams require safe schema change review, rollback capability, and data-loss protection. 9 existing CI/CD pipelines need review for Fabric Warehouse deployment safety before cutover.
Remediation options:
Add manual approval gates Add schema diff review step Define rollback plan per deployment Add data-loss checks pre-deployment
